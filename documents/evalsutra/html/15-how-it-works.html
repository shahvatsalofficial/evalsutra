How it works

A plain-language tour with pictures. No code knowledge needed.

The idea in one sentence#

You write the rules first, record what the agent actually did, and let a deterministic program compare the two.

WordPlain meaning
SuiteYour list of rules
CaseOne situation you test
AssertionOne rule inside a case
ObservationWhat the agent did in that situation
GateThe overall decision

How one rule is judged#

Missing information is its own answer. It is never rounded up to a pass.

Which evidence counts#

Strong evidence

Can prove pass or fail

  • PASS + FAILactual_runYou ran the agent and recorded it
  • PASS + FAILimported_traceLogs from a real run
  • PASS + FAILhuman_labelA person checked it
  • PASS + FAILtest_fixtureControlled sample data
Weak evidence

Can only prove fail

  • FAIL ONLYmodel_judgeOpinion of another model
  • FAIL ONLYunverified_claimThe agent says it worked

A would-be pass becomes inconclusive. A failure still counts, because acting on a problem is safe.

How the final decision is made#

GO_CANDIDATE means your recorded evidence met your thresholds. A person still decides whether to release.

Why sample size matters#

An 80% pass rate on 5 cases and on 1000 cases are not the same knowledge. EvalSutra prints a 95% Wilson interval so you can see the uncertainty.
