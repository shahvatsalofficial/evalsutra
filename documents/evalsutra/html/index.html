How it works

From your rules to a decision

You write what good looks like. EvalSutra compares it with what actually happened.

Write rules

Say what must and must not happen.

{ "type": "forbidden_tools",
  "tools": ["export_customers"] }

Record the run

Save what your agent really did.

{ "sourceType": "actual_run",
  "toolCalls": ["search_kb"] }

Get the verdict

Reports for people and CI.

evalsutra run --suite s.json \
  --observations o.json --out out
Evidence first

Not all evidence is equal

A confident agent, or another model praising it, is not proof.

Strong evidence

Can prove pass or fail

  • PASS + FAILactual_runYou ran the agent and recorded it
  • PASS + FAILimported_traceLogs from a real run
  • PASS + FAILhuman_labelA person checked it
  • PASS + FAILtest_fixtureControlled sample data
Weak evidence

Can only prove fail

  • FAIL ONLYmodel_judgeOpinion of another model
  • FAIL ONLYunverified_claimThe agent says it worked

A would-be pass becomes inconclusive. A failure still counts, because acting on a problem is safe.

Proof

We audit ourselves in public

Run npx evalsutra audit to reproduce this. It is a self-check, not a third-party certification.

What EvalSutra does not do

  • It does not run your agent or call any AI model.
  • A GO_CANDIDATE result is not deployment approval or a safety certificate.
  • Live agent runner, sandbox, server and dashboard are planned, not built.
  • Skill discovery inside live editors is not verified.
